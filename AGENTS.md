# Agent Guidance For d2-diagrams

This repository is a portable Agent Skill package for designing, converting,
validating, rendering, and troubleshooting D2 diagrams. It is documentation,
styles, templates, a curated gallery, metadata, and a few helper scripts — not an
application.

When a user asks for D2 diagrams, diagram-as-code, text-to-diagram conversion,
diagram validation/rendering, or D2 troubleshooting, read `SKILL.md` first.
`SKILL.md` is the canonical skill entrypoint; this file is always-on repository
guidance for agents maintaining the package.

## The thing this package is for

The skill teaches an agent to behave like a visual designer, not a D2 compiler.
The central behaviour is the loop in `SKILL.md`: build the semantic model, style
it deliberately, render candidates across layout engines, **look at the rendered
image**, and revise until it passes the visual rubric. A successful render is not
a quality gate. Changes that weaken that loop are regressions, however tidy they
look in source.

## Repository Model

Progressive disclosure: `SKILL.md` is always loaded, everything else is pulled in
on demand.

- `SKILL.md` — primary entrypoint and trigger surface. Keep it lean: behaviour,
  hard rules, and the decision tables. Detail belongs in `references/`.
- `references/*.md` — deeper material:
  - `visual-design-guide.md` — the design system and the visual rubric.
  - `layout-and-medium-guide.md` — render/inspect loop, engines, output mediums.
  - `d2-language-reference.md` — syntax, shapes, styles, imports, layout, export.
  - `diagram-pattern-cookbook.md` — practical diagram recipes.
  - `conversion-guide.md` — Mermaid, PlantUML, Graphviz, prose.
  - `rendering-and-validation.md` — CLI usage, helper scripts, CI.
  - `troubleshooting.md` — common mistakes and fixes.
  - `source-notes.md` — research links.
- `styles/*.d2` — the visual system. `semantic-classes.d2` holds the class
  vocabulary with no colors; every other pack spreads it and adds a palette.
- `templates/*.d2` — copy-ready starting points, referenced by file stem by
  `scripts/scaffold_d2.py`.
- `gallery/*/` — finished diagrams with `design-notes.md` and a committed
  `preview.svg`. This is the package's visual teaching material.
- `tests/smoke.d2`, `tests/fixtures/probe-*.d2` — toolchain and style-pack checks.
- `MANIFEST.md`, `README.md`, `CLAUDE.md`, `agents/openai.yaml` — metadata or
  alternate front doors. Keep them consistent with `SKILL.md`.

## Maintenance Rules

- Preserve portability across Claude Code, Codex, Hermes Agent, Pi, and other
  Agent Skills-compatible runtimes. Avoid runtime-specific assumptions.
- Use relative paths from the package root. The skill may be copied anywhere.
- Treat D2 source as canonical. Renders are disposable — **except**
  `gallery/**/preview.svg`, which is committed reference material and is
  regenerated by `scripts/render_gallery.sh`.
- Keep the D2 CLI optional. The skill must remain useful for source-only
  authoring, and scripts must fail clearly (exit 127) when `d2` is unavailable.
- Add semantic classes to `styles/semantic-classes.d2` (structure only), then
  give every variant pack a palette entry for them. A class that exists in one
  pack and not the others will silently do nothing.
- Never combine a `**` recursive glob with a map inside `vars` (such as
  `d2-config`) — it fails with `"style" needs a value`. And never give a `**`
  glob a `${...}` substitution value: that crashes d2 outright. This is why the
  packs carry style values on classes.
- When adding, removing, or renaming package files, update `MANIFEST.md` and any
  affected `README.md` examples.
- When changing `SKILL.md` frontmatter, preserve Agent Skills spec validity.

## Diagram Quality

Every `.d2` in this repo is an example of what the skill teaches, so it has to
follow the rules in `references/visual-design-guide.md`:

- A thesis comment at the top saying what the diagram is for, and what was left
  out on purpose.
- Stable lowercase snake_case IDs, distinct from display labels; connect by key.
- Semantic containers, styled quieter than their contents.
- An edge hierarchy: primary flow heavy and labeled, dependencies thin, async
  dashed, failure dashed and labeled. Every edge earns its place.
- Styling through a style pack's classes, not per-node hex values.
- Red/amber/green reserved for failure/warning/success.
- Minimal manual positioning.

Before committing a change to any `.d2`, render it and look at it. A file that
compiles is not a file that works.

## Useful Commands

```bash
# Render layout candidates and write a contact sheet (the main authoring loop).
scripts/review_d2.py templates/system-architecture.d2 --dark --png

# Validate syntax and compile.
scripts/check_d2.sh tests/smoke.d2
scripts/check_d2.sh $(git ls-files '*.d2')

# Render to a specific format; D2_* environment variables carry the overrides.
scripts/render_d2.sh templates/sequence-diagram.d2 /tmp/sequence.svg
D2_LAYOUT=elk D2_THEME=4 scripts/render_d2.sh templates/system-architecture.d2 /tmp/system.svg

# Compile the D2 examples embedded in the Markdown.
scripts/validate_docs.py

# Regenerate or drift-check the committed gallery previews.
scripts/render_gallery.sh
scripts/render_gallery.sh --check

# List and scaffold.
scripts/scaffold_d2.py list
scripts/scaffold_d2.py styles
scripts/scaffold_d2.py create sequence-diagram ./login-flow.d2 --medium docs

# Formatting is enforced in CI.
d2 fmt $(git ls-files '*.d2')
```

If the D2 CLI is unavailable and only documentation changed, use static review
plus `git diff --check`. If `.d2` files or Markdown examples changed and `d2` is
available, run `scripts/check_d2.sh` and `scripts/validate_docs.py`.
